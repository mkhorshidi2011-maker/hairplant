# راهنمای استفاده از پرامپت‌های Kilo Code

## ترتیب کار

1. پوشه `kilo-prompts` را کنار پروژه نگه دار و فایل `PROJECT_BRIEF.md` را به ریشه پروژه کپی کن. این فایل مرجع اصلی است و همه فازها به آن ارجاع می‌دهند.
2. هر فاز را **جداگانه** و به ترتیب به Kilo Code بده (محتوای فایل را در چت Kilo Code بچسبان).
3. بعد از هر فاز، خروجی را بررسی کن و فقط وقتی راضی بودی فاز بعد را بفرست.
4. حالت پیشنهادی: فاز ۰ در **Architect**، فازهای ۱ تا ۶ در **Code** (یا Orchestrator).

| فایل | کار |
|---|---|
| `phase-0-plan.md` | برنامه‌ریزی بدون کد (منتظر GO) |
| `phase-1-foundation.md` | پایه پروژه، RTL، layout، سیستم رسانه موقت |
| `phase-2-home.md` | صفحه اصلی و کامپوننت‌ها |
| `phase-3-content-pages.md` | صفحات روش‌ها، مجله، گالری و بقیه صفحات |
| `phase-4-reservation-admin.md` | رزرو، دیتابیس، پیامک، پنل ادمین |
| `phase-5-seo-qa.md` | سئو، دسترس‌پذیری، تست |
| `phase-6-deploy.md` | استقرار و مستندات تحویل |

## جایگزینی رسانه‌های موقت (بعد از تحویل)

همه تصویرها و ویدیوها با سیستم اسلات ساخته می‌شوند، پس نیازی به تغییر کد نیست:

1. `pnpm media:report` را اجرا کن تا `MEDIA_SLOTS.md` بسازد. این فایل می‌گوید هر اسلات چه ابعادی دارد و کجا استفاده می‌شود.
2. فایل واقعی را با **نام اسلات** در `public/media/` بگذار. مثال: `hero-main.webp`، `intro-video.mp4`، `gallery-03-before.webp` و `gallery-03-after.webp`. برای ویدیو، تصویر poster را با نام `intro-video-poster.webp` بگذار.
3. `pnpm media:sync` را اجرا کن تا مانیفست `content/media.json` به‌روز شود و status به `final` برود.
4. `pnpm media:check` را اجرا کن تا ببینی کدام اسلات‌ها هنوز موقت‌اند.
5. پیش از انتشار نهایی، build را با `MEDIA_STRICT=1` بزن تا اگر چیزی موقت مانده باشد خطا بدهد.

نکته: تصویرها را قبل از گذاشتن، به webp یا avif و با حجم معقول (زیر ۲۰۰ تا ۳۰۰ کیلوبایت برای تصاویر معمولی) تبدیل کن. برای نمایش تصویر بیماران رضایت‌نامه کتبی داشته باش.
